## 1. MVP 범위

MVP는 **매일 기록이 한 곳에 쌓이게 하는 최소 기능**입니다 (1차 핵심 병목: 기록이 쌓이지 않음). 외부 서비스 키가 필요한 기능(AI 분석, 알림)은 배포 뒤 추가 구축에서 붙입니다.

### 1-1. MVP에 넣는 것

| 화면 | 기능 | 근거 |
|---|---|---|
| 로그인 | 구글 계정 로그인, 대표님 계정 1개만 허용 | 4차 4-2 |
| 오늘 | 이번 주 KPI(운동 횟수·식사 사진·인바디 판정), 오늘 루틴 체크리스트(아침 컨디션, 식사 3끼, 영양제 + 모두 먹음, 보충제·쉐이크, 운동), 루틴 완료 표시 | 3차 3-1, 5차 목업 |
| 달력 | 날짜별 상태(완료·놓친 항목 있음·기록 없음·오늘·미래), 고른 날의 빠진 항목 보기와 채우기 | 3차 3-5 |
| 운동 | 운동 홈(루틴·다음 차례), 운동 고르기(검색·부위·기구·최근·여러 개·새 운동), 운동 기록(지난번 값 채움, 세트 +/−, 러닝, 메모, 운동 후 컨디션, 체중), 운동별 기록(최근 5회 볼륨), 루틴 편집 | 5차 목업 v2 |
| 식단 | 끼니별 사진(카메라·앨범, 줄여서 저장), 직접 입력(그램·칼로리·단백질), 메모, 오늘 합계 | 3차 3-3, U2·U9 |
| 몸 변화 | 체중·인바디 입력, 기간(1·3·6개월) 추세, 좋음/주의, 컨디션 추이 | 3차 3-4 |
| 설정 | 내 루틴, 운동 목록(기본 + 내가 만든 운동, 숨기기), 영양제·보충제 목록 | 3차 1-2 |
| 공통 | 입력 범위 검사와 "맞나요?" 확인, 입력 중 임시 저장, 삭제 되돌리기, 저장 두 번 눌러도 한 번만, 아이폰 홈 화면에 추가 | 4차 5장, U6~U8 |

### 1-2. 뒤로 미루는 것

| 기능 | 언제 | 이유 |
|---|---|---|
| 식사 사진 AI 분석 + 새벽 재분석 | 추가 구축 | Gemini 키와 서버 기능이 필요. MVP에서는 사진만 올려도 식사 칸이 채워지고, 칼로리는 직접 입력 |
| 아이폰 알림 (10시·22시, 시스템 문제) | 추가 구축 | 배포된 주소와 홈 화면 추가가 있어야 시험 가능 |
| 엑셀 내려받기 | 추가 구축 | 기록이 쌓인 뒤에 필요 |
| 주 1회 백업, 서버 깨우기, 상태 점검 | 배포(CI/CD) | GitHub Actions로 배포와 함께 설정 |

## 2. 구현 방식 (기본값)

| 항목 | 방식 | 이유 |
|---|---|---|
| 검수판 | 예시 기록이 들어간 체험판을 휴대폰에서 바로 눌러 볼 수 있게 올림. 체험판 기록은 그 기기에만 저장 | 실제 서버 연결 전에 화면과 흐름부터 검수 |
| 실제 서버 연결 | 검수 및 안정화 단계에서 Supabase·구글 로그인 연결. 계정 만들기는 그때 단계별 안내 | 대표님 계정으로 만들어야 하는 것들이라 한 번에 안내 |
| 하루 상태·주간 KPI 계산 | MVP에서는 화면에서 계산. 서버 계산(4차 2-3의 계산 기능)은 알림을 붙일 때 함께 추가 | 알림 전까지는 서버가 상태를 알 필요가 없음 |
| 기본 운동 목록 | 자주 쓰는 헬스 운동 약 100개를 직접 정리해 넣음 | 5차 결정 |

## 3. MVP 구축 결과 (2026-10-15)

### 3-1. 만든 것

| 화면 | 주소 | 담은 것 |
|---|---|---|
| 오늘 | `/today` | 이번 주 KPI, 오늘 루틴(아침 컨디션 바로 입력, 식사 + 단백질·칼로리 두 줄 요약, 영양제 + 모두 먹음, 보충제·쉐이크, 운동 + 운동 칼로리, 운동 후 컨디션), 남은 항목 수·완료 표시. 지난 날짜도 열어 채울 수 있음 |
| 달력 | `/calendar` | 월 달력(월요일 시작), 날짜별 상태, 고른 날의 빠진 항목과 채우기 |
| 운동 홈 | `/workout` | 루틴(다음 차례 강조, 러닝 루틴은 목표와 마지막 러닝), 지난 운동 그대로, 운동 골라서 시작, 최근 운동, 오늘 운동 요약과 지난번 대비(러닝은 페이스 차이·목표 달성) |
| 운동 기록 | `/workout/log` | 지난번 값 표시·미리 채움, 세트 +/−, 운동 메뉴(위로·아래로·바꾸기·빼기), 러닝(거리·평균 페이스, 시간 자동 계산, 목표 달성 표시), 메모, 운동 후 컨디션, 체중, 입력 중 자동 임시 저장, 범위 검사와 "맞나요?" 확인 |
| 운동 고르기 | (기록·루틴 화면 안) | 검색, 부위 탭, 기구 필터, 최근 한 운동, 여러 개 고르기, 새 운동 만들기 |
| 운동별 기록 | `/workout/exercise/:id` | 지난번 기록, 최근 5회 볼륨 막대와 세트 목록, 오늘 기록에 추가. 러닝은 이번 달 거리·평균 페이스·시간, 최고 기록(가장 긴 거리, 가장 빠른 페이스), 최근 5회 |
| 루틴 편집 | `/workout/routines` | 루틴 고르기·새로 만들기(헬스/러닝)·지우기, 이름, 운동 순서, 세트 수. 러닝 루틴은 목표 거리·평균 페이스 |
| 식단 | `/meals` | 오늘 먹은 양(단백질 목표 체중 × 1.5~2g 대비 차이, 먹은 칼로리와 쓴 칼로리 비교), 쉐이크 먹음 체크(먹은 날 단백질·칼로리에 더함), 끼니별 사진(줄여서 저장), 시간·메뉴·양·칼로리·단백질·메모, 사진 바꾸기·지우기(되돌리기) |
| 몸 변화 | `/body` | 기간 1·3·6개월, 인바디 4개 수치와 좋음/주의, 체중 추이·입력·고치기, 아침 컨디션 추이 |
| 설정 | `/settings` | 내 루틴, 운동 목록(숨기기·내가 만든 운동 고치기), 영양제·보충제 추가·수정·숨기기(식단에 더할 1회 양·단백질·칼로리), 계정 |

- 기본 운동 목록 103개(웨이트 102 + 러닝), 3분할 루틴 예시 3개와 러닝 루틴 1개(목표 5km), 영양제·보충제 9종이 처음부터 들어 있습니다.
- 서버 표 구조와 보안 규칙: [supabase/migrations/0001_init.sql](../supabase/migrations/0001_init.sql). 대표님 계정만 가입·접근 가능, 본인 기록만 읽고 쓰기, 범위 밖 값은 서버에서도 거부. 시험용 데이터베이스에서 다른 계정 차단·범위 검사·중복 방지를 확인했습니다.
- 계산 규칙 시험: `npm test` (하루 루틴 상태, 주간 KPI, 인바디 판정, 다음 차례, 지난번 값, 입력 범위).

### 3-2. 구현하며 정한 것 (기본값)

| 항목 | 정한 값 | 이유 |
|---|---|---|
| 식사 칸 채움 | 사진을 올리거나, 사진 없이 메뉴·칼로리를 적어도 채운 것으로 봄 | 사진을 깜빡한 끼니도 기록으로 남기기 위해 |
| 식사 "확인함" | MVP에서는 메뉴·칼로리 등을 직접 적으면 "확인함", 사진만 있으면 "사진만" | AI 추정이 없으므로 |
| 아침·운동 후 컨디션 | 두 점수를 모두 고르면 바로 저장 (저장 버튼 없음) | 체크리스트에서 한 번에 끝내기 위해 |
| 운동 기록 저장 후 | 오늘 화면으로 이동 (보충제 체크가 이어지도록) | 5차 목업 흐름 |
| 맨몸 운동 무게 | 무게 칸을 비우면 0kg(맨몸)으로 저장 | 풀업·딥스 등 |
| 지난번 값 비교 | 같은 운동의 같은 세트 번호끼리 비교해 30% 넘게 다르면 확인 | 웜업 세트가 확인에 걸리지 않게 |
| 저장 실패 | 기기에 모아 두고 연결되면 순서대로 다시 보냄. 화면 위에 "저장 대기 N건" 표시 | 4차 5장 인증 만료·실행 실패 |
| 영양제 목록 변경 | 지우지 않고 숨김. 숨긴 항목은 루틴 완료 조건에서 빠짐 | 지난 기록 보존 |
| 러닝 루틴과 다음 차례 | 러닝 루틴은 헬스 루틴의 "다음 차례" 순서에 끼지 않음. 운동 홈에서 헬스 루틴 아래에 따로 보임 | 러닝은 헬스 분할과 따로 도는 날이라 |
| 러닝 칸 채움 | 지난번 러닝의 거리·페이스로 채움. 지난번이 없으면 루틴 목표로 채움 | 헬스의 "지난번 값 채움"과 같은 방식 |
| 러닝 페이스 범위 | 1km당 2분~30분 밖이면 저장 막음. 지난번보다 30% 넘게 다르면 "맞나요?" | 잘못 적은 값 거르기 |
| 러닝 목표 달성 | 목표 거리 이상 달리고, 목표 페이스가 있으면 그보다 빠르거나 같으면 "목표 달성" | 나이키 런처럼 목표 대비 확인 |
| 러닝 위치 추적 | 넣지 않음. 달린 뒤 거리와 평균 페이스를 옮겨 적음 | 홈 화면 웹앱은 화면이 꺼지면 위치 기록이 멈춤 |
| 단백질 목표 기준 체중 | 그날 체중, 없으면 그 전 마지막 체중. 체중 기록이 없으면 목표 대신 "체중을 적으면 나와요" | 체중은 이틀에 한 번 적기 때문에 |
| 먹은 양 합계 | 칼로리·단백질 숫자가 있는 끼니만 더함. 사진만 있는 끼니는 "숫자가 없어 빠졌다"고 따로 알림 | AI 분석 전에는 사진만으로 숫자를 알 수 없음 |
| 쓴 칼로리 | 기초대사량 + 일상 활동(기초대사량의 20%, 앉아서 일하는 하루) + 운동. 기초대사량은 최근 인바디 값, 없으면 체중 × 24 | 운동 칼로리만 먹은 칼로리와 비교하면 늘 크게 남는 것처럼 보여서, 하루 전체로 비교 |
| 운동 칼로리 | 쉬는 동안 쓰는 몫을 뺀 활동 칼로리 (애플워치 "활동 칼로리"와 같은 뜻). 러닝: 체중 × 거리(km) × 1kcal. 헬스: (MET − 1) × 체중 × 운동 시간 | 기초대사량과 두 번 세지 않게 |
| 헬스 운동 시간과 강도 | 운동 시간은 세트 수 × 3분(쉬는 시간 포함)으로 어림. MET는 운동 후 "운동 강도 느낌" 1~2점 3.5, 3점(또는 없음) 5, 4~5점 6 | 운동 시간을 따로 적지 않아도 되게 (최소 입력) |
| 오늘 칼로리 비교 | 오늘은 "지금까지" 먹은 양과 하루 전체 쓴 칼로리를 비교 | 하루가 끝나기 전에도 얼마나 남았는지 보이게 |
| 쉐이크 성분 | 1회 40g(대표님), 단백질 36g·150kcal (WPI 일반값: 단백질 약 90%, 1g당 약 3.7kcal). 설정에서 제품 영양표대로 고침 | 제품마다 성분이 조금씩 달라서 |
| 쉐이크 먹음 기록 | 오늘 화면의 쉐이크 체크와 식단 화면의 "먹음"은 같은 기록. 어느 쪽에서 눌러도 식단 합계에 더해짐 | 한 번만 누르면 되게 |
| 식단에 더하는 보충제 | 설정에서 단백질이나 칼로리를 적은 영양제·보충제는 모두 같은 방식으로 더함 (지금은 쉐이크만) | EAA 등도 필요하면 같은 칸에 적으면 됨 |
